# 实体卡片规范（LB-032 草案）

> **状态**：草案 **v0.0.1**（`sheet_version` 0.0.1）。本文件是**提案级**规范：数字全部来自代码与
> 数据文件（`card_dictionary.json` / `aruco_dictionaries.json` / `synth_layouts.json`），
> 没有实测依据的项一律标「**待实测**」，任何打印、基材、可识别距离的结论都属人工验证。
>
> 与 `docs/ROADMAP.md` LB-032 的对应关系：范围、验收、不做三项均按该条目执行，ROADMAP 的范围与
> 优先级**一个字节都没改**。

## 0. 范围与边界

**本单做什么**

- 卡片尺寸、标记尺寸、静区、基材、打印工艺、批次编号与质检项的规范草案（本文件）；
- `liveblocks cardsheet` 生成可打印的标记页：A4 排版，含裁剪线、静区、卡片编号与朝向标记，
  输出 PNG 或 PDF；
- 手绘降级版说明（黑白格加编号，供没有打印机时用，见 §9）。

**本单不做什么**

- 不声称任何打印工艺、基材、可识别距离、打印后模块精度的**实测**结论（见 §4、§5、§11）；
- 不替用户决定最终卡面美术：卡面沿用 LB-002 的卡面版式定义（`synth_layouts.json`），
  美术与配色由人定，本单只保证「标记 + 静区 + 编号 + 朝向」这些**识别相关**的几何；
- 不写固件、不烧写、不做硬件 bring-up；不改 `docs/ROADMAP.md` 的范围与优先级；
- 不改仓库 / CI / 超级代理设置；不直接推 `main`；不合并 PR。

**数字纪律**（本文件的底线）

1. 每个数字都能追到**字典 / 位表 / 卡面版式 / 静区规则**，或它们的算术派生（§2 的「可追溯」行）；
2. 追不到的（排版参数与实体项）显式标「**待实测**」，不写「应该够」「一般够用」这类没有依据的话；
3. `tests/test_sheet_docs.py` 双向核对：文档缺数字、文档多出无处可追的数字、正文冒出没有出处的
   「数字 + 单位」、命令写错、`LB-S0xx` 码漏写，都会失败（含反向验证：删一行必须报缺口）。

## 1. 一条命令

```bash
# ① 生成标记页：PNG + PDF + 清单（清单 = 这一页应该长什么样的机器可读声明）
liveblocks cardsheet render --out sheet.png --pdf sheet.pdf --manifest sheet.json

# ② 验收：把页面重新识别一遍，逐卡核对 id / 朝向 / 位置，并核对「同参数两次字节一致」
liveblocks cardsheet verify

# ③ 手绘降级版：每张卡的 8×8 模块格子印成文字（没打印机时照着抄）
liveblocks cardsheet stencil --out stencil.txt

# ④ 规范里每个数字的出处（可追溯 / 待实测）
liveblocks cardsheet spec
```

真跑输出（默认参数：A4、`card-60x40` 版式、4 px/mm、批次 `lb-b0001`）：

```
已写出标记页 sheet.png（840×1188 px @ 4 px/mm，A4 210×297 mm，16 张卡 / 1 页）
已写出 PDF sheet.pdf（9389 字节，页面按 A4 整页铺满）
  静区：卡面声明 2.5 mm，规则 4 mm（1 个模块 4 mm），卡间距 6 mm
```

`liveblocks cardsheet verify` 的验收对照逐条打印「通过 / 未通过 + 依据」（真实数字，见 PR 记录）：

```
[通过] 标记页重新识别读出全部 16 张卡的 id —— 读出 16/16；未登记候选 0 个
[通过] 每张卡的朝向读数与清单一致（angle ≈ 0°） —— 16/16 张卡在 ±1.5° 内
[通过] 把页面转 90°/180°/270° 后朝向跟着转（排除「朝向恒为 0°」的假通过）
[通过] 识别出的卡片中心与清单卡槽中心吻合（≤ 3 px）
[通过] 同参数两次渲染 PNG / PDF / 清单逐字节一致
```

## 3. 静区规则

静区（quiet zone）= 标记四周必须保持的净白区域。本单只定义一条规则（实现见
`liveblocks/sheet/spec.py` 的 `quiet_zone_rule_mm`）：

    静区下限 = max(卡面版式声明的 marker_quiet_zone_mm, 1 个模块边长)
    1 个模块边长 = 标记边长 ÷ 模块总数（含黑边）

两条约束的含义：

1. **卡面内**：卡面版式声明了标记四周的静区（`card-60x40` 版式 2.5 mm、`card-40x40` 版式 2 mm）。
   打印时标记四周只保证这圈净白；
2. **卡片之间**：卡片互不相邻，卡间距必须不小于静区规则，否则相邻卡片的墨迹会侵入静区——这条在
   `spec.validate()` 里是硬校验（不满足直接报 `LB-S001`，不会静默出图）。

**已知差异（如实写，不粉饰）**：`card-60x40` 版式的卡面静区 2.5 mm **小于**静区规则 4 mm（1 个模块）；
也就是说「卡面内的净白比规则少」。合成管线上不影响识别（§1 的 verify 有证据），但**实体卡上够不够用
必须实测**：见 §11 的第 3 条人工步骤。

## 4. 基材（待实测）

**待实测**：本单没有出样，所以不选型、不给推荐值。要落地时至少要回答：

- 厚度：卡片能不能平放在桌面（翘曲会让标记平面偏离相机假设）；
- 白度 / 不透明度：薄纸背面印字会不会透过来，变成标记旁边的「假黑块」；
- 表面：亚光/亮面（墨粉反光、镜面反射）；
- 耐久：反复抓取后边缘磨损对标记黑边的影响。

候选（**不是推荐**，只是要测的对象）：80 g 普通纸、200 g 卡纸、PVC 卡、亚克力片。判据与步骤见 §11。

## 5. 打印工艺（待实测）

**待实测**：本单没有打印机、没有出样，因此不声称任何工艺的可用性，也不声称最小可打印模块。

要测的三件事：

1. **比例**：必须 100% 原尺寸打印（关掉「适应页面 / Fit to page」）——不同打印机的默认缩放不同，
   缩放会让卡片实际尺寸偏离卡面版式标称值，进而让识别层的「标记尺寸」注册失效；
2. **边缘质量**：标记黑边是否连贯、最小模块是否断线或糊边（模块 4 mm，是标记边长 24 mm 的六分之一）；
3. **对比度**：黑墨与纸面的灰度差是否足够（识别层用局部自适应阈值，但极端低对比仍会失败）。

判据与步骤见 §11。手绘降级版（§9）是「没有打印机」时的替代路径，而**不是**打印工艺的替代结论。

## 6. 批次编号

规则（实现见 `liveblocks/sheet/manifest.py`，清单里每张卡都有 `serial`）：

    serial = <batch_id>-p<页号两位>-<位号两位>      例：lb-b0001-p01-07

- `batch_id` 由**人**给（`--batch`），**不由时钟生成**——否则「同参数两次输出字节一致」不成立，
  清单也不能当快照；
- 位号是「页内卡槽顺序」（从 1 起，按行优先），与卡片字典的顺序一致；
- `card_id`（`C01` / `N01` / `O01` …）来自卡片字典，是链路里引用卡片的键；批次号只用于实体管理；
- 清单是批次的可核对记录：改批次号 → 清单与产物指纹全变，所以**重打一批就换一个 `batch_id`**。

## 8. 标记页排版（A4）

页面上有什么（全部在同一张灰度光栅里，`liveblocks cardsheet render` 一次画出）：

1. **卡面**：整张卡面由 LB-002 的卡面渲染器画出（圆角、描边、标记、标签），所以打印页上的卡与
   合成场景里的卡是同一份画法；
2. **静区**：标记四周刷白（版式声明的静区，§3），卡片之间再留卡间距；
3. **裁切线**：每张卡外围一圈浅灰细线（线宽、与卡片的间距见 §2 表里的「设计默认值」，两者都
   **待实测**——线太细打不出来、太粗会压墨）；
4. **卡片编号**：卡面标签位上的 `card_id` + `card_face`（由卡面版式决定，点阵字形只支持 ASCII）；
5. **朝向标记**：每张卡面左下角一个实心三角形，尖朝卡片上边；页面上边另有一个「TOP」三角，
   规定「页面上边 = 朝向 0°」。识别侧读到的面内角（逆时针为正）在页面上就是 0°；
6. **页眉 / 页脚**：版式名、批次号、页码、静区规则与「沿灰线剪」的说明。

**为什么是 4 px/mm**：识别层的默认自适应窗口是 21 px，模块在 4 px/mm 下是 16 px，两者配合得
最好（窗内能看到模块与邻域）。这是**实现参数**，不是「打印质量」的结论：要更高分辨率就用
`--pixels-per-mm 6` 之类，但重识别时可能要同步加大 `--block`（`cardsheet verify --block`）。
打印质量与分辨率是否够用 = **待实测**。

**多页**：容量不足时自动分页（清单里每张卡带 `page` / `row` / `col`）；本单 16 张卡在容量 18 的
A4 上刚好一页，多页路径有单元测试但没有出样验证。

## 9. 手绘降级版

没有打印机时用 `liveblocks cardsheet stencil`：每张卡一张 8×8 的字符格子（外圈 1 格是静区、内圈
6×6 是标记，其中外圈 1 格要涂黑做黑边）。真跑输出（`C01` 那张，节选）：

```
C01（marker_id=0，card_face=move-forward）
  每格 4 mm，6×6 格；四周再留 4 mm 静区不画
  # = 涂黑，. = 不涂，空 = 静区（留白）
  +----------------+
  |                |
  |  ############  |
  |  ##..##....##  |
  |  ####..##..##  |
  |  ######....##  |
  |  ######..####  |
  |  ############  |
  |                |
  +----------------+
  卡片上边朝上 = 朝向 0°；抄完沿 6 mm 的方格外沿剪下
```

怎么用：

1. 拿一张方格纸（每格 4 mm），按网格把 `#` 涂满；
2. 四周留出 1 格（4 mm）不画 = 静区；
3. 卡片上边朝上抄，抄完剪下——朝向就由「上边」定义，与打印版的朝向 0° 一致；
4. 抄完用 `liveblocks recognize detect --image <照片>` 复核：**抄错一个格**就会变成另一个码字
   （字典里 50 个码字互不为旋转等价，但抄错成另一个码字是真会发生的）。

网格是从位表直接生成的（`sheet.stencil.marker_code`），所以手抄版的每个格子都能追到
`aruco_dictionaries.json` 的码字：`tests/test_sheet_stencil.py` 用 `parse_stencil_blocks` 把文字
反解回 6×6 位串，逐卡与位表比对（16 张卡全中，说明这份「说明」不是摆设）。

## 10. 诊断码（`LB-S0xx`）

| 码 | 标题 | 触发点 |
| --- | --- | --- |
| `LB-S001` | 版面参数非法 | 纸张/像素密度/页边距/卡间距/裁切线/批次号不合法，或卡间距小于静区规则 |
| `LB-S002` | 标记与静区放不进卡面 | 版式的标记 + 静区超出卡面尺寸 |
| `LB-S003` | 卡片放不进一页 | 按当前参数一张卡都排不下，或卡片数超出可排版页数 |
| `LB-S004` | 重识别卡片 id 与清单不符 | 清单里的卡没有被读出，或读出候选没有卡片身份 |
| `LB-S005` | 朝向读数与清单不符 | 面内角超出容差，或读到了身份但没有角度读数 |
| `LB-S006` | 同参数两次输出字节不一致 | 两次渲染的 PNG / PDF / 清单任一不一致 |
| `LB-S007` | 规范数字缺少溯源 | 文档里的数字追不到字典/规则，或待实测项没有标注 |

这些码不进 `docs/PROTOCOL.md` §9（那是层间诊断的码区间），只用于本层的自检与验收报告。

## 11. 待人工验证

**实体卡打印尺寸（是否 100% 原尺寸）**

① 生成：`liveblocks cardsheet render --out sheet.png --pdf sheet.pdf`；
② 打印时关掉「适应页面 / Fit to page」，按 100%（实际尺寸）出纸；
③ 卡尺量任意 3 张卡的长边与短边（卡面版式 `card-60x40` 标称 60×40 mm）与任一标记边长（标称 24 mm），
把实测值连打印机型号一起记进 Issue；
④ 偏差超过 1 mm 先查打印缩放，**不要**回头改标称值。

**打印后模块边长与边缘质量**

① 打印同一张页；② 放大镜或手机微距看任一标记的 6×6 模块：黑边是否连贯、最小模块有没有断线或糊边；
③ 卡尺量 6 个模块的总长（标称 24 mm）并记实测；④ 结论写进 `docs/PROGRESS.md` 的「待硬件验证」，
不要写成「已验证」。

**卡面 2.5 mm 静区在实体卡上是否够用**

卡面声明静区 2.5 mm **小于**静区规则 4 mm（1 个模块）。① 把打印好的卡紧贴另一张卡、再紧贴深色
桌面/深色物件摆放；② 用 `liveblocks serve-cam serve` 抓 10 帧以上，看 `liveblocks recognize detect`
是否仍给出正确 `marker_id`；③ 若漏检，把「静区不足」记进 Issue，再决定是否提高版式的
`marker_quiet_zone_mm`（改版式要重生成 fixtures）。

**基材与打印工艺**

① 选一种基材（80 g 纸 / 200 g 卡纸 / PVC）与一种工艺（激光 / 喷墨 / 外协）；② 按上一条打印并测量；
③ 记录翘曲、反面透印、墨粉反光对识别的影响；④ 只有实测记录才能把「基材」「打印工艺」两项从
「待实测」移出。

**可识别距离与角度**

① 实体卡平放桌面，用 `liveblocks serve-cam serve` 在 0.3 / 0.5 / 0.8 m 与 0° / 15° / 30° 倾角
各抓 10 帧；② 记检出率与漏检帧；③ 结论必须带设备型号、分辨率、距离、帧数，缺一项就不算实测。

**裁切线是否实用**

① 按灰线手剪一张卡；② 量剪出来的卡与标称尺寸的偏差；③ 若裁切线压在卡面墨迹上或离得太远，
记下实际手剪偏差，再决定是否调整 `CUT_GAP_MM`（属下一轮的设计改动，不在本单）。

> 这六条与 `liveblocks/sheet/spec.py` 的 `HUMAN_VERIFICATION` 逐条对应（`tests/test_sheet_docs.py`
> 会核对），所以「待实测」不会被悄悄改成「已验证」。

## 12. 已知限制

1. **合成管线 ≠ 实体卡**：`cardsheet verify` 只是把渲染出来的像素当成一帧再识别（无镜头畸变、无
   运动模糊、无真实光照），它能证明「版面几何 + 标记编码 + 清单」自洽，不能证明打印件可识别；
2. **分辨率与识别窗口耦合**：默认 4 px/mm 是为识别层的 21 px 自适应窗口选的；提高分辨率后默认窗口
   可能读不出（实测 6 px/mm 时真实标记会被"当成本地背景"），要么同步加大 `--block`，要么下调分辨率；
   这条是**实现耦合**，不是打印结论；
3. **单页优先**：本单只对「16 张卡 / 一页」出过证据；多页排版的代码路径有单测，没有出样；
4. **点阵字形只有 ASCII**：卡面标签与页眉页脚只能是 ASCII，中文卡片名（`label` 字段）不进像素；
5. **卡面文字可能产生额外候选**：默认参数下重识别的候选数正好等于卡片数（0 个未登记候选），但在更高
   分辨率下卡面文字会被检出为「形状对、身份未定」的候选（`status=occluded` / `ambiguous`）——这是
   LB-003 的已知行为，**不是**本单新引入的误检；
6. **PDF 只是一个整页图像**：不可搜索、无矢量文字；线条与文字都在光栅里，放大到很高倍数会看到像素；
7. **裁切线是灰线不是矢量裁切标记（Marks）**：手剪误差没有实测；
8. **没有卡面美术结论**：颜色、图案、正反面印刷都在本单之外。

## 13. 协议缺口（本单只报告、不改 `docs/PROTOCOL.md`）

1. §11 只说「卡片字典的登记格式」未定义，**没有**任何「卡片物理规范」的槽位：卡面尺寸、标记尺寸、
   静区、基材、批次号都无处安放（本单落在 `docs/CARD-SPEC.md` + `sheet` 清单里）；
2. §3.2 的 `orientation_quadrant` 只有 4 个象限，且本实现里它是**注册信息**（`CardRegistry`），
   不是从图像读出来的；「一张卡在页面上的朝向」这种页面级朝向没有表示法；
3. §8 的运行记录没有「标记页 / 打印清单」这类产物的 `kind`，产物的指纹（像素/PDF sha256）也没有槽位；
4. §9 没有本层的码区间（本单用 `LB-S0xx`，不进协议）；
5. 「同一个 `card_id` 可以有多个物理副本（批次）」在协议里没有表达方式（`marker_id` 唯一、`card_id`
   唯一），批次只存在于清单里。

以上都只**报告**，未改 `PROTOCOL.md`（`AGENTS.md` §5：改协议要仓库所有者确认）。
