# 序界（LiveBlocks）硬件说明 — 待验证

> **状态：全部条目均为待验证（未选型确认 / 未实测）。** 本文件不含任何已验证结论。
> 任何一项要从未验证变为已验证，必须按 `.github/ISSUE_TEMPLATE/hardware-test.md` 提交实测记录并附证据（照片、日志、万用表读数、示波器截图、测量数据）。

## 1. 待验证的选型

### 1.1 摄像头（S1 采集）

| 候选项 | 关注点 | 风险 | 验证方式 |
| --- | --- | --- | --- |
| USB UVC 免驱摄像头（1080p30，定焦） | 免驱、跨平台、便宜 | 卷帘快门在移动/抖动时角点模糊；自动曝光会改变对比度 | 静态与轻抖条件下的 ArUco 检出率、角点重复性 |
| 工业级 UVC（全局快门、可关自动曝光/自动白平衡） | 曝光与增益可锁，识别稳定 | 价格、驱动开关是否可编程 | 锁曝光后不同光照下的检出率与姿态抖动 |
| 树莓派 CSI 摄像头（如 Camera Module 3） | 与主机一体、体积小 | 需特定主机与驱动链路；广角畸变大 | 视场与畸变校正效果、帧率 |
| 手机/笔记本内置摄像头（仅开发期） | 零成本 | 视场与安装位置不可控 | 仅用于早期联调，不作为方案 |

待定参数：分辨率、视场角、最近对焦距离、工作距离范围、是否需要补光、安装高度与俯角。**Q1/Q7 依赖本项结论。**

### 1.2 主机（运行识别与执行）

| 候选项 | 关注点 | 风险 |
| --- | --- | --- |
| 笔记本 / 迷你主机（x86_64） | 算力充足、调试方便 | 体积与供电不适合成品形态 |
| 树莓派 5 / 同类 SBC | 一体机形态、GPIO 可用 | 散热、USB 供电余量、OpenCV 性能 |
| MCU（ESP32-S3 等） | 低成本、低功耗 | 算力不足以跑完整识别链路，需前后端拆分（Q10） |

待定：CPU 架构、内存、是否需要 GPU/NPU 加速、操作系统与 Python 版本、启动方式（手动 / 开机自启，后者需另行授权）。

### 1.3 显示与反馈（S7）

| 候选项 | 关注点 | 风险 |
| --- | --- | --- |
| 直接复用开发机屏幕（调试界面） | 零额外硬件，首阶段即可用 | 不是产品形态 |
| HDMI 小屏（5–10 寸） | 界面自由度高 | 供电、走线、外壳开口 |
| SPI/I2C 小屏（MCU 直驱） | 成本低、与 MCU 匹配 | 刷新率与分辨率有限 |
| LED 灯带 / 点阵（WS2812 等） | 反馈直观、成本低 | 电源电流峰值、电平匹配、数据线时序 |
| 蜂鸣器 / 扬声器 | 无视觉依赖的反馈 | 噪声环境、扰民 |

首阶段（软件闭环）**不依赖**任何显示硬件，反馈只做调试界面叠加（见 Q6）。上表仅为后续阶段备选。

### 1.4 实体卡片（S2 输入侧对象）

| 候选项 | 关注点 | 风险 |
| --- | --- | --- |
| 纸质卡 + 激光/喷墨打印 | 迭代快、成本低 | 反光、墨色深浅导致对比度不足；纸张翘曲 |
| 亚克力/雪弗板 + 贴标 | 刚性、平整 | 边缘高光反射、厚度造成阴影 |
| PVC 卡（标准卡尺寸） | 耐用、规格统一 | 表面光泽需哑光处理 |

待定：卡片尺寸、标记尺寸与静区（quiet zone）、基材厚度、表面处理（哑光/覆膜）、卡片数量上限、标记字典（见 Q1/Q2）。**未实测前不得给出「可识别距离」之类的数字结论。**

## 2. 电源待确认项

| ID | 待确认内容 | 为什么重要 | 确认方式 |
| --- | --- | --- | --- |
| PW-1 | 整机输入电压与供电方式（USB-PD / DC 适配器 / PoE） | 决定线材、接口与外壳 | 选定主机与屏后核算 |
| PW-2 | 峰值电流预算（主机 + 摄像头 + 屏 + 灯效同时满载） | 灯带峰值可能导致复位或掉压 | 实测峰值电流，留 ≥30% 余量 |
| PW-3 | 摄像头供电是否独立（避免 USB 供电不足导致掉帧） | 掉帧直接影响识别 | 带载实测 + 日志中的掉帧计数 |
| PW-4 | 屏与灯效是否需要独立电源与共地 | 共地不良会造成通信误码 | 接线图 + 实测 |
| PW-5 | 是否需要断电保护/软开关，关机流程 | 突然断电可能损坏存储 | 方案评审 |
| PW-6 | 散热与持续功耗（长时间运行时温升） | 降频会导致识别延迟 | 连续运行 ≥1h 的温度记录 |

**以上全部为待确认，尚无实测数据。**

## 3. 引脚待确认项

仅在采用 MCU 分支（Q10）时生效；主机直连方案下本节的引脚项不适用，但仍需确认 USB 拓扑与端口分配。

| ID | 待确认内容 | 说明 |
| --- | --- | --- |
| PN-1 | 摄像头接口（USB 端口分配 / CSI 排线 / DVP 并口） | 端口数量与带宽 |
| PN-2 | 显示总线（SPI / I2C / HDMI）及片选、DC、RST 引脚 | 与灯效数据脚不可复用 |
| PN-3 | 灯效数据线引脚与电平（3.3V / 5V 转换） | WS2812 类需要电平与电容匹配 |
| PN-4 | 按键 / 编码器 / 急停输入引脚与上拉方式 | 急停是否必须，待定 |
| PN-5 | 调试串口（UART）与烧写口（SWD/JTAG）保留 | 必须保留，禁止占用 |
| PN-6 | 中断脚与保留脚清单 | 防止与后续功能冲突 |
| PN-7 | 地线与屏蔽（摄像头排线、灯带长线） | EMC 与稳定性 |
| PN-8 | 启动模式脚 / 复位脚的实际接线 | 影响无法启动时的恢复 |

**引脚表尚未绘制，也不存在权威接线图。任何实现不得硬编码引脚号。**

## 4. 环境与安装待确认

- 桌面材质与颜色（深色哑光更利于对比度，待验证）。
- 环境光：是否需要顶部补光、是否受窗光/顶灯频闪影响。
- 工作距离与俯角范围，以及卡片可放置区域（有效视场）。
- 摄像头固定方式（支架 / 悬臂），是否允许用户移动（影响标定策略，Q7）。

## 5. 硬件验证流程（人工）

1. 用 `.github/ISSUE_TEMPLATE/hardware-test.md` 开 Issue，写清原因、设备、准备、步骤、预期、通过标准。
2. 实测并保留证据：照片、视频帧、串口日志、电流/电压读数、温度。
3. 在 Issue 中回填「对应版本」（commit/PR/固件版本号）与「反馈状态」。
4. 结论只在 `docs/PROGRESS.md` 的「待硬件验证 → 已验证」迁移时生效；代理不得自行迁移。
